# Demo video script (under 6 minutes)

Record the hosted app at 1440×900 or larger, with the saved readmission audit open. The saved demo opens at *Depends on review*; confirming the proposed feature loads the saved confirmed audit instantly. Speak to the screen; every number below is on screen.

| Time | Screen | What to say |
|---|---|---|
| 0:00–0:30 | Experiment tab, the quoted claim | "This notebook claims a hospital-readmission model with AUC 0.94, ready to deploy for all adults. Results like this get published and deployed every day. Many are inflated by data leakage, where information from the test set or from the future slips into training." |
| 0:30–1:00 | "How a verdict is reached" | "Tools like LeakageDetector and NBLyzer can spot leakage patterns in code. But a detected pattern isn't the same as a wrong result: a 2026 study of 2,047 datasets found some leaks barely matter while others dominate. LeakVerity asks the question that matters: does this claim survive once the leaks are fixed?" |
| 1:00–1:35 | Click **Run it live**, show the progress list, then cut to the saved audit | "It runs the notebook in a sandbox and records every split, every fit and every score. Before measuring anything, it replays the protocol it reconstructed and checks that it reproduces the author's own number: 0.9390. If it can't, LeakVerity refuses to issue a verdict." |
| 1:35–2:35 | **Investigation** | Walk the protocol strip (scaler on all rows, keep best). Then the five findings: "Each finding comes from execution evidence: 60 test rows are exact copies of training rows; 332 patients are on both sides of the split; a feature, follow-up ER visits in the next 30 days, looks like it isn't known at discharge; and the author picked the best of ten random seeds on the test set. That feature is only *proposed*: an AI or a rule can suspect a leak, but only a person who knows the data can confirm it. So LeakVerity evaluates the claim both ways." Point at the scenario table: "If the feature is a leak, the claim is overstated. If it's legitimate, the claim holds. So the verdict is *Depends on review*." Click **Confirm: not available at prediction time**. "I confirm it: the audit re-runs with my decision recorded." |
| 2:35–3:25 | **Repair** | "LeakVerity keeps the author's data preparation and rewrites only the evaluation, marking every change. Then it runs the corrected code under the same tracer: it printed 0.703069, exactly what the replay engine predicted, and its own trace proves nothing is fitted before the split, no patient is on both sides, and the future feature is gone. Seven checks, all pass." |
| 3:25–4:15 | **Impact**, the drain gauge | "Every combination of fixes was re-run on several splits. Reported 0.939; verified 0.709, 95% CI 0.68 to 0.74. The Shapley attribution shows where the 0.23 went: almost all of it was the future feature. Picking the best seed added a real 0.006 (its confidence interval excludes zero). And fitting the scaler before the split, the textbook leak, changed nothing. LeakVerity says so instead of crying wolf." |
| 4:15–4:50 | **Survival tests** | "On the corrected protocol: stable across 20 splits, it holds on future admissions, but for patients 65 and over the AUC is only 0.60. The claim said all adult patients." |
| 4:50–5:15 | **Certificate** | "With the feature confirmed, the verdict is Overstated, and the certificate records my decision, the rule that produced it, hashes of the inputs and every number traceable to an execution log." Show the clean control's verdict: Supported, zero leaks. |
| 5:15–5:45 | Benchmark table (README) | "Is it right in general? On 24 generated studies where we know the true answer, LeakVerity …" (read the headline numbers from BENCHMARK.md). |
| 5:45–6:00 | Closing | "The AI reads the notebook and explains. Re-executed code produces every number. Fixed rules decide the verdict. LeakVerity: find the leak, measure the damage, test the claim." |
